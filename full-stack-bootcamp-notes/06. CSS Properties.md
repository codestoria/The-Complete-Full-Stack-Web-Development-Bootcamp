## Introduction

This guide covers three foundational areas of CSS: **colors**, **fonts**, and **the box model**.

These three topics appear in almost every stylesheet you will ever write. They are also the vocabulary you need in order to read, understand, and debug other people's CSS — whether that CSS belongs to a teammate, a framework, or a project you inherited.

Each section follows the same structure:

- **What** the feature is, and **why** it matters.
- **How** to use it, with small, focused examples.
- **What to watch out for**, so you can recognize common mistakes early.

By the end, you will have a working mental model of how CSS styles text and lays out boxes, plus a small complete example that brings all three areas together.

## 1. CSS Colors

### 1.1 Why colors matter

Color is one of the first things a visitor notices. It sets the tone of a page, establishes visual hierarchy, and strongly affects readability.

CSS offers several ways to specify a color, and each format has its strengths. Knowing them helps you build a consistent palette and communicate precisely with designers and other developers.

### 1.2 The two properties you will use most

Most color work is done with just two properties:

- **`color`** — sets the **text color** of an element.
- **`background-color`** — sets the **background color** painted behind the element's content and padding. By default, the background extends to the border box (`background-clip: border-box`), so it also extends under the border area; an opaque border will cover it.

```css
body {
  background-color: red;
}

h1 {
  color: blue;
}
```

The `body` element wraps everything on the page, so setting its `background-color` colors the entire page. The `h1` rule changes only the heading's text color.

> **Tip:** When you are unsure what a property does, check **MDN Web Docs** (developer.mozilla.org). It is the authoritative reference for CSS.

### 1.3 Named colors

CSS defines over 140 **named colors** — human-readable keywords such as `red`, `blue`, `cornflowerblue`, `cadetblue`, `dimgrey`, and `olivedrab`.

- **Advantage:** readability. `background-color: papayawhip;` is immediately understandable.
- **Disadvantage:** you are limited to a fixed set of names.

To see the full list, search for "MDN named colors". The MDN table also shows the equivalent hex code for each name, which is useful when converting between formats.

> **Note on CSS Levels:** You may see colors labeled "CSS Level 1", "Level 2", and so on. These labels indicate *when* a color was added to the specification. You do not need to worry about levels — just use what works in the browsers you are targeting.

### 1.4 Hex codes

When you need a color that has no name — for example, a specific shade from a designer's palette — use a **hex code**:

```css
background-color: #5d3891;
```

A hex code begins with `#` (required) followed by three, four, six, or eight hexadecimal digits. The most common form is six digits; the other forms are shorthands or include transparency, as described below.

### 1.5 How color is represented: RGB and hex

Screens display color by mixing three primary colors: **red**, **green**, and **blue** (RGB). Each channel has a value from `0` to `255`:

- `0` means none of that color.
- `255` means the maximum amount of that color.

For example, the purple `#5d3891` corresponds to:

- Red: 93 out of 255
- Green: 56 out of 255
- Blue: 145 out of 255

A **hex code** is simply a different way of writing those same three numbers, using base-16 (hexadecimal). Each pair of characters represents one channel:

| Channel | Decimal | Hex |
|---------|---------|-----|
| Red     | 93      | 5D  |
| Green   | 56      | 38  |
| Blue    | 145     | 91  |

Put them together: `#5D3891`. Case does not matter. The `#` prefix tells the browser that the following characters are a hex color.

You do not need to convert between RGB and hex by hand — design tools and color pickers do it for you. What matters is that you **recognize** a hex code and know that it represents a precise color.

#### Other hex forms

The six-digit form (`#RRGGBB`) is the one you will use most. CSS also supports three additional hex forms:

| Form | Example | Meaning |
|------|---------|---------|
| `#RGB` | `#F00` | Shorthand for `#FF0000` (each digit is doubled) |
| `#RGBA` | `#F008` | Like `#RGB`, plus an alpha (transparency) channel |
| `#RRGGBBAA` | `#FF000080` | Six-digit color plus an alpha channel |

The alpha channel works like the fourth value in `rgba()` (see below): in `#RRGGBBAA`, `00` is fully transparent and `FF` is fully opaque; in `#RGBA`, the single alpha digit is expanded in the same way (`0` → `00`, `F` → `FF`). This guide focuses on the six-digit form because it is the most common; the other forms are worth recognizing when you encounter them.

> **Tip:** `rgb(93, 56, 145)` is the functional equivalent of `#5D3891`. Both describe the same color. The hex form is more compact; the `rgb()` form makes the three channels explicit. Modern CSS also supports a fourth value for transparency, e.g. `rgba(93, 56, 145, 0.5)` or the newer syntax `rgb(93 56 145 / 0.5)`. A value of `0` is fully transparent; `1` is fully opaque.

### 1.6 Finding color palettes: Color Hunt

The built-in named colors are limited. For a more distinctive, harmonious palette, a free tool such as **colorhunt.co** is excellent. It offers professionally designed palettes — groups of four colors that look good together.

In a typical palette, you might assign:

- one color as the page `background-color`
- one as the `h1` text color
- one as the `h2` or subtitle color
- one as an accent color for buttons or links

Each color in a Color Hunt palette is shown with its hex code. Copy the hex code and paste it into your CSS:

```css
h1 {
  color: #f9f9f9;
}
```

You can also find hex codes next to each named color in the MDN documentation, so you can switch between formats freely.

### 1.7 Quick reference: color formats

| Format | Example | When to use |
|--------|---------|-------------|
| Named color | `red`, `cornflowerblue` | Quick prototypes, readable code |
| Hex code | `#5D3891` | Custom palettes, design tools |
| RGB (functional) | `rgb(93, 56, 145)` | When you need to compute channels dynamically, or to add transparency |

> **Key takeaway:** Named colors are convenient and readable. Hex codes give you access to any color. Both are valid everywhere a color value is accepted.

## 2. Font Properties

### 2.1 Why font properties matter

Text is the primary content of most websites. CSS lets you control how that text looks: its size, weight, typeface, alignment, and line spacing. These properties directly affect readability and the overall feel of a page. A well-chosen font size and line height can make the difference between a page that is comfortable to read and one that is exhausting.

This section covers five key properties:

- `font-size`
- `font-weight`
- `font-family`
- `text-align`
- `line-height`

### 2.2 `font-size`

The `font-size` property sets the size of the text. You can specify it in several units, each with different behavior. Choosing the right unit matters because it determines how your text scales when the page is resized or when a user changes their browser's default font size.

#### Pixels (`px`)

```css
p {
  font-size: 20px;
}
```

A pixel is a tiny unit of measurement. On a standard display, `1px` is approximately **1/96 of an inch**, or about **0.26 mm**. Pixels are **absolute**: `20px` is always `20px`, regardless of the surrounding context.

> **Note:** On high-resolution ("Retina") screens, one CSS pixel may be rendered using multiple physical pixels, but the CSS unit itself remains consistent. This is why a `20px` font looks sharp on both a standard monitor and a high-DPI phone screen.

#### Points (`pt`)

```css
p {
  font-size: 12pt;
}
```

A point is slightly larger than a pixel: **1/72 of an inch**, or about **0.35 mm**. Points are commonly used in print design and in applications like Microsoft Word. When you select a "12" font size in Word, you are selecting 12 points.

> **Note:** On the web, `px` and `rem` are more common than `pt`. Points are mainly useful in print stylesheets, where the output is measured in physical units.

#### `em`

The `em` unit is pronounced /ɛm/, the same as the name of the letter **M** — not as the two letters "E-M" (ee-em). The name is often described as coming from the width of the capital letter **M** in a typeface; in modern CSS, however, `1em` is simply relative to the relevant `font-size`, as explained below.

In modern CSS, `1em` means different things depending on which property it is used on:

- On properties such as `padding`, `margin`, `width`, or `line-height`, `1em` equals the **element's own computed `font-size`**.
- On the `font-size` property itself, `1em` equals the **parent's font size** — which is why `font-size: 2em` doubles the inherited size.

To understand `em`, you first need to know about **inheritance**. In CSS, if an element does not set its own `font-size`, it inherits the font size of its parent. This inheritance chain continues up to the root element (`<html>`), which has a browser-defined default (usually `16px`).

For properties other than `font-size`, `1em` therefore means "the font size this element has ended up with, whether set directly or inherited."

For `font-size` itself, `2em` means "twice the parent's font size." If the element does not set its own `font-size`, its computed font size equals the parent's, so for other properties 1em resolves to the same base size.

```css
body {
  font-size: 20px;
}

h1 {
  font-size: 2em; /* 2 × 20px = 40px */
}
```

If the parent (`body`) has `font-size: 20px`, then `1em` inside it equals `20px`, and `2em` equals `40px`. If you later change the body to `40px`, the `h1` automatically becomes `80px`.

This is powerful, but it can become confusing when elements are nested several levels deep. Because each element's `em` is based on its own inherited size, nested elements multiply:

```css
body   { font-size: 20px; }
div    { font-size: 1.5em; }  /* 30px */
div p  { font-size: 1.5em; }  /* 1.5 × 30px = 45px, not 30px */
```

The paragraph ends up at `45px`, not `30px`, because its `1.5em` is relative to the `div`'s `30px`, not the body's `20px`. You have to trace the chain of parents to know what `1em` actually resolves to — and that chain can be hard to follow when your CSS lives in a separate file from your HTML.

#### `rem` (root em)

The `rem` unit is **relative to the root element** (usually the `<html>` element), not the immediate parent.

```css
html {
  font-size: 20px;
}

h2 {
  font-size: 2rem; /* 2 × 20px = 40px, regardless of parent */
}
```

Because `rem` always refers to the same root, it is **consistent and predictable**. If you change the root font size, every `rem`-based size scales together — which is excellent for responsive design and accessibility.

#### Comparing `em` and `rem`

Consider this HTML:

```html
<body>
  <footer>
    <h2>Subtitle</h2>
  </footer>
</body>
```

If `footer` has `font-size: 20px` and `h2` has `font-size: 2em`, the `h2` becomes `40px`. If you later change `footer` to `80px`, the `h2` becomes `160px` — its size moves with its parent.

If instead `h2` has `font-size: 2rem`, changing `footer` has **no effect**. Only changing the root (`html`) font size affects it.

> **Recommendation:** Use `rem` for font sizes. It gives you a single point of control (the root size) and avoids the confusion of tracing nested parent sizes — especially when your CSS lives in a separate file from your HTML.

#### Named sizes

CSS also provides keywords: `small`, `medium`, `large`, `x-large`, `xx-large`, etc. These are convenient but less precise. Their exact pixel values are defined by the browser and can vary slightly between browsers, so they are best used for quick prototypes rather than precise designs.

#### Summary of `font-size` units

| Unit | Relative to | Example | Behavior |
|------|-------------|---------|-----------|
| `px` | Nothing (absolute) | `20px` | Always 20px |
| `pt` | Nothing (absolute) | `12pt` | Always 12pt (≈ 16px) |
| `em` | On `font-size`: parent's font size. On other properties: the element's own `font-size`. | `2em` | Doubles the relevant base size; compounds when nested |
| `rem` | Root font size | `2rem` | Doubles the root's size; consistent regardless of nesting |
| keyword | Browser default | `large` | Predefined scale, varies slightly between browsers |

### 2.3 `font-weight`

The `font-weight` property controls how light or bold the text appears.

**Keyword values:**

```css
p {
  font-weight: normal; /* default, equivalent to 400 */
}

strong {
  font-weight: bold;   /* equivalent to 700 */
}
```

**Numeric values (commonly 100–900; modern CSS allows 1–1000):**

```css
h1 {
  font-weight: 900; /* very heavy */
}

.light {
  font-weight: 300; /* light */
}
```

The commonly used scale runs from `100` (thinnest) to `900` (thickest); CSS Fonts Level 4 permits the full range `1`–`1000`. Not every font supports every weight; if a weight is unavailable, the browser picks the closest available one. This is why a `font-weight: 900` rule might look identical to `font-weight: 700` on a font that only ships in regular and bold.

**Relative keywords:**

- `lighter` — selects a lighter weight relative to the inherited weight.
- `bolder` — selects a heavier weight relative to the inherited weight.

The exact mapping depends on the inherited weight and on which weights the font actually provides. The CSS specification defines these mappings by ranges of inherited weights, but the practical result is that these keywords move you to a noticeably lighter or heavier available weight — not necessarily a single step on the 100–900 scale. If precision matters, set the numeric value directly.

> **Note:** `font-weight` only works as expected if the font family you are using actually includes those weights. Many web fonts offer only regular (400) and bold (700). If you need a range of weights, check the font's available weights before designing around them.

### 2.4 `font-family`

The `font-family` property specifies the typeface used for text.

```css
body {
  font-family: Helvetica, Arial, sans-serif;
}
```

This rule says: "Use Helvetica if it is available; otherwise use Arial; otherwise fall back to the browser's generic sans-serif font."

#### Why the fallback list matters

`Helvetica` is commonly available on macOS, but many Windows computers do not have it installed. If you wrote only `font-family: Helvetica;` and the user did not have Helvetica, the browser would fall back to its default font — which might be something quite different.

By providing a comma-separated list of alternatives ending in a **generic family**, you ensure a sensible result on every system. This is not a minor detail: fonts are installed on the user's operating system, not bundled with your website (unless you load a web font — see below). You cannot assume that any specific font is present on every device.

#### Generic font families

| Generic family | Description | Example typefaces |
|----------------|-------------|-------------------|
| `serif` | Has small decorative "feet" at the edges of letters | Times New Roman, Georgia |
| `sans-serif` | Clean edges, no feet | Arial, Helvetica, Verdana |
| `monospace` | Every character occupies the same width | Courier New, Consolas |
| `cursive` | Curly, handwriting-like | Platform-dependent; often a script or handwriting font |
| `fantasy` | Decorative, playful | Platform-dependent; often a display or decorative font |

Generic families are resolved by the browser and operating system, so they look different on different machines — but they always produce *something* reasonable. This is why they are the correct final entry in every `font-family` list.

#### Font names with spaces

If a font name contains spaces, it is best to wrap it in quotation marks:

```css
p {
  font-family: "Times New Roman", Times, serif;
}
```

Quotation marks are not strictly required for every multi-word name — the CSS specification allows an unquoted family name to consist of several identifiers separated by spaces. But quoting is the safer habit: it removes any ambiguity, and it is required when the name contains characters that are not valid in an identifier (e.g. a name starting with a digit, or containing punctuation). It also makes the intent obvious to anyone reading the CSS.

#### Using custom web fonts

If you want a font that is not installed on your users' computers, you can load it from a web font service. **Google Fonts** (fonts.google.com) is a free and popular option.

The process:

1. Browse fonts.google.com and select a font (and optionally specific weights, e.g. regular 400, bold 700).
2. Copy the `<link>` tag that Google provides.
3. Paste the `<link>` into the `<head>` of your HTML, **before** your `<style>` tag or external stylesheet link.
4. Copy the `font-family` CSS rule that Google provides (or write your own) and apply it to your elements.

> **Placement note:** Put the Google Fonts `<link>` inside `<head>`, **outside** `<style>`. This guide consistently places it *before* the `<style>` tag (or any external stylesheet link). Either order works in practice; the only hard requirement is that the `<link>` is in `<head>` and not inside `<style>`.

Example:

```html
<head>
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Caveat&amp;display=swap">
  <style>
    h1 {
      font-family: "Caveat", cursive;
    }
  </style>
</head>
```

Because the font is loaded from Google's servers, it works for any user who can reach those servers, regardless of their operating system or installed fonts. If the request fails (offline, blocked, or the service is down), the browser falls back to the next font in the list — which is exactly why the generic fallback matters.

> **Important:** Always include a generic fallback (e.g. `cursive`) after your custom font name, in case the link fails to load. A missing font should never make your text unreadable.

### 2.5 `text-align`

The `text-align` property controls the horizontal alignment of text within its container.

```css
h1 {
  text-align: center;
}

p {
  text-align: left; /* explicit left; in modern CSS the initial value is `start`, which resolves to left in LTR */
}

.right-aligned {
  text-align: right;
}
```

You can also use `start` and `end`, which are **direction-aware** (they depend on the element's writing direction):

- In a left-to-right language (English), `start` = left, `end` = right.
- In a right-to-left language (Arabic, Hebrew), `start` = right, `end` = left.

This makes `start` and `end` more flexible for internationalization than `left` and `right`. Other values (such as `justify`) exist; consult MDN for the full list.

### 2.6 `line-height` (a brief note)

`line-height` controls the vertical space between lines of text. It is not strictly a font property, but it has a major effect on readability and is commonly set alongside `font-size`.

```css
p {
  font-size: 16px;
  line-height: 1.6; /* computed value stays 1.6; used line-height = 1.6 × 16px = 25.6px */
}
```

A unitless value like `1.6` is relative to the element's own `font-size`, which makes it scale predictably. For body text, values between `1.4` and `1.8` are typical. We will use `line-height` in the final example.

> **Why unitless?** If you wrote `line-height: 25.6px`, the line height would stay fixed even if the font size changed. A unitless value recalculates whenever the font size changes, which is almost always what you want.

### 2.7 Quick reference: font and text properties

| Property | Purpose | Common values |
|----------|---------|---------------|
| `font-size` | Size of text | `16px`, `1.2rem`, `12pt`, `large` |
| `font-weight` | Thickness of strokes | `normal`, `bold`, `100`–`900`, `lighter`, `bolder` |
| `font-family` | Typeface | `"Helvetica Neue", Arial, sans-serif` |
| `text-align` | Horizontal alignment | `left`, `right`, `center`, `start`, `end` |
| `line-height` | Vertical space between lines | `1.5`, `24px`, `normal` |

> **Key takeaway:** Use `rem` for predictable sizing, always provide font fallbacks, and load custom fonts through a service like Google Fonts when you need a typeface that users may not have installed.

## 3. The Box Model: Margin, Padding, and Border

### 3.1 The core idea: every element is a box

In CSS, **every HTML element is treated as a rectangular box**. Even if you cannot see the box (because it has no border or background), it exists and governs how the element is laid out.

The **box model** describes the four layers of that box, from outside in:

```
┌───────────────────────────────────────┐
│                Margin                 │
│  ┌─────────────────────────────────┐  │
│  │             Border              │  │
│  │  ┌───────────────────────────┐  │  │
│  │  │          Padding          │  │  │
│  │  │  ┌─────────────────────┐  │  │  │
│  │  │  │       Content       │  │  │  │
│  │  │  │  (width × height)   │  │  │  │
│  │  │  └─────────────────────┘  │  │  │
│  │  └───────────────────────────┘  │  │
│  └─────────────────────────────────┘  │
└───────────────────────────────────────┘
```

- **Content** — the actual text, image, or child elements. Its size is set by `width` and `height`.
- **Padding** — space *inside* the border, between the content and the border.
- **Border** — a visible (or invisible) line around the padding.
- **Margin** — space *outside* the border, between this element and neighboring elements.

Understanding which layer is which is the single most important skill for laying out pages. Most "why is this element in the wrong place?" bugs come down to margin, padding, or border being different from what you expected.

### 3.2 Width and height

```css
.box {
  width: 200px;
  height: 300px;
}
```

These set the size of the **content area**. You can use pixels for fixed sizes or percentages for sizes relative to the parent:

```css
.full-width {
  width: 100%; /* fills the parent's width */
}
```

> **Important:** By default, `width` and `height` refer to the *content box only*. Padding and border are added **on top** of these dimensions (unless you change `box-sizing` — see §3.7). This is a common source of confusion. For example, `width: 200px` with `20px` padding and `10px` border on each side actually occupies `260px` of horizontal space.

### 3.3 Border

The `border` property is a shorthand that accepts up to three components:

```css
.box {
  border: 10px solid black;
}
```

The three components are:

1. **Thickness** — e.g. `10px`, `2px`, `thin`.
2. **Style** — e.g. `solid`, `dashed`, `dotted`, `double`.
3. **Color** — any named color, hex code, or RGB value.

The conventional order is thickness, then style, then color, and you should write it that way for readability. However, CSS does not enforce a fixed order for these three components — `border: solid 10px black` is also valid, because the values are unambiguous (only one is a length, only one is a style keyword, only one is a color). The browser parses each value according to its type, not its position.

Changing the thickness makes the line thicker or thinner:

```css
border: 30px solid black;
```

Changing the style to `dashed`:

```css
border: 10px dashed black;
```

> **Crucial behavior (default `content-box` sizing):** Increasing the border thickness does **not** change the element's specified `width` or `height`. The border grows **outward** from the content box. The content area stays the same size, but the element's total footprint increases. (If you use `box-sizing: border-box`, the border is included in `width`, so the content area shrinks instead — see §3.7.)

> **Tip:** `border-radius` rounds the corners of the border, e.g. `border-radius: 6px`. It is often used with a border to create card-like components.

### 3.4 Overriding individual sides

After setting a general border, you can override specific sides with more specific properties:

```css
.box {
  border: 30px solid black;
  border-top-width: 0px;
}
```

The second declaration overrides the top border width to `0`, removing the top border. **Order matters**: the override must come *after* the general shorthand declaration. (If the declarations are in separate rules, the later rule wins when specificity is equal.)

> **A brief note on specificity:** Not all rules are equal. A selector like `#header .box` is more specific than `.box`, so it wins even if it appears earlier. DevTools shows overridden rules with a strikethrough, which is the easiest way to see which rule actually applies. For now, remember: when two rules conflict, the more specific selector wins; if they are equally specific, the later rule wins.

#### The multi-value shorthand: clockwise order

`border-width`, `padding`, and `margin` all accept **one to four values**, applied in **clockwise order** starting from the top:

| Number of values | Order of application |
|------------------|----------------------|
| 1 value | All four sides |
| 2 values | Top & bottom, then left & right |
| 3 values | Top, then left & right, then bottom |
| 4 values | Top, right, bottom, left |

Examples:

```css
/* All sides 10px */
border-width: 10px;

/* Top & bottom 10px, left & right 20px */
border-width: 10px 20px;

/* Top 10px, left & right 20px, bottom 30px */
border-width: 10px 20px 30px;

/* Top 10px, right 20px, bottom 30px, left 40px */
border-width: 10px 20px 30px 40px;
```

The same pattern applies to `padding` and `margin`. This shorthand is worth memorizing: it appears constantly in real-world CSS.

### 3.5 Padding

**Padding is space inside the border**, between the content and the border.

```css
.box {
  padding: 20px;
}
```

With a `10px` border and `20px` padding, the visual result is:

- The content area (e.g. text) sits in the middle.
- 20px of empty space surrounds the content on all sides.
- Then the 10px border.
- Then the margin (outside).

Padding **pushes the border outward** from the content. Under the default `content-box` sizing, when the element has an explicit `width` or `height`, padding does not change the content area's specified size; it simply adds breathing room *inside* the box and increases the element's total size. (For an auto-width block element, adding horizontal padding can instead reduce the content area, because the used width is constrained by the containing block.)

This is most visible when the element contains text: without padding, text touches the border; with padding, there is comfortable space between them. Padding also extends the element's background color, which is why backgrounds often appear to "fill" the space around text.

Padding accepts the same one-to-four-value clockwise shorthand as `border-width`.

### 3.6 Margin

**Margin is space outside the border**, between this element and other elements.

```css
.box {
  margin: 10px;
}
```

If two elements sit side by side, each with `margin: 10px` on the left and right, the gap between them is `20px` (10px from each). Margin creates space *between* elements in a way that padding cannot.

> **Margin collapse:** When two vertical margins meet (e.g. the bottom margin of one block and the top margin of the next), they *collapse* into a single margin. If both margins are positive, the result is the larger of the two — not their sum. For example, if one block has `margin-bottom: 20px` and the next has `margin-top: 10px`, the gap between them is `20px`, not `30px`. Negative margins follow more complex rules: when one margin is positive and one is negative, the result is the sum (so `20px` and `-10px` collapse to `10px`); when both are negative, the result is the more negative value. Horizontal margins do not collapse. For this guide, be aware that collapse exists; it mainly affects vertical spacing between block-level elements.

Margin also accepts the clockwise shorthand:

```css
margin: 0 10px;      /* 0 top & bottom, 10px left & right */
margin: 20px 0 0 0;  /* 20px top only */
margin-left: 260px;  /* push element 260px from the left */
```

> **Tip:** `margin: 0 auto;` horizontally centers a block-level element whose used width is narrower than its container. The `auto` value tells the browser to split the remaining horizontal space equally between the left and right margins. The width can come from an explicit `width` or from a `max-width` constraint (as in the `.card` example later in this guide).

### 3.7 The `box-sizing` property (important aside)

By default, `width` and `height` refer to the **content box**. If you set `width: 200px` and then add `20px` padding and `10px` border on each side, the element actually occupies:

```
200px (content) + 20px (left padding) + 20px (right padding)
                + 10px (left border)  + 10px (right border)
= 260px total width
```

This surprises many people. To make `width` include padding and border, use:

```css
* {
  box-sizing: border-box;
}
```

Many developers apply this rule globally at the start of every project. It makes sizing far more intuitive: `width: 200px` means the element is 200px wide *including* padding and border.

> **Note:** With `border-box`, when the element's `width` is fixed, increasing padding or border thickness reduces the content area instead of increasing the element's total width. This is the key behavioral difference from `content-box`.

> **Why is `content-box` the default?** Because it was the original CSS behavior, and changing it would break existing websites. `border-box` was added later as an opt-in because it matches how designers and developers usually think about sizing ("200px means 200px").

### 3.8 Visualizing the box model in DevTools

Chrome DevTools shows a box model diagram in the Styles/Computed area (usually near the bottom of the Styles pane; the exact location varies slightly by DevTools version). It color-codes:

- **Margin** (outermost, typically orange/yellow)
- **Border** (typically yellow/brown)
- **Padding** (typically green)
- **Content** (innermost, typically blue)

You can click any value in the diagram and edit it live — changes apply instantly. This is the fastest way to understand how margin, border, and padding interact on a real element.

### 3.9 The `<div>` element: creating your own boxes

HTML elements like `<p>` and `<img>` create boxes automatically. But sometimes you want to **group several elements together** into one box so you can style or position them as a unit. For this, use the `<div>` element — short for "division".

```html
<div class="card">
  <img src="photo.jpg" alt="A photo">
  <p>A caption for the photo.</p>
</div>
```

A `<div>` has **no visual appearance by default**. It is invisible. Its only purpose is to act as a container. You give it meaning and appearance through CSS:

```css
.card {
  border: 1px solid #ccc;
  padding: 16px;
  margin: 20px;
  width: 300px;
}
```

Divs are essential for layout: you can wrap sections, apply a shared background, or position a group of elements together.

Because divs are invisible, debugging layout issues involving them can be hard. This is where a tool like **Pesticide** (a free Chrome extension) helps: it outlines every element on the page with a colored dashed line, so you can see the boxes, their nesting, and their sizes. Hovering over an outline tells you the element's tag name, classes, and IDs.

> **Note:** By default, `<div>` elements are **block-level**: they start on a new line and take up the full width available. Other elements, like `<span>`, are **inline**: they sit within the flow of text. We will not cover `display` in depth here, but it is worth knowing that the box model applies to both types.

### 3.10 Worked example: three boxes side by side

Suppose you want three `div` boxes, each with a `200px × 200px` content area, arranged horizontally. Each box has `20px` padding and a `10px solid black` border.

**Step 1: Calculate each box's total width.**

Under the default `content-box` sizing, the total horizontal space each box occupies is:

```
200px (content) + 20px + 20px (padding) + 10px + 10px (border) = 260px
```

So each box takes up 260px, not 200px. Remember this figure whenever you need to know how much room a box really needs.

**Step 2: Put the boxes in a row.**

By default, `<div>` elements are block-level and stack vertically. To place them side by side, set `display: inline-block` (or use a modern layout system such as Flexbox, covered elsewhere). With `inline-block`, the boxes flow in document order, like words on a line: Box 2 naturally sits to the right of Box 1, and Box 3 to the right of Box 2. **You do not need to add `margin-left` to Box 2 or Box 3 just to make them follow one another.** Normal flow already handles that.

**Step 3: Watch out for whitespace between `inline-block` elements.**

A subtle detail: any whitespace in the HTML between `inline-block` elements (a newline, a space, indentation) renders as a visible gap roughly one space character wide. If the container is sized to fit exactly `3 × 260px`, this gap is enough to push the third box onto a new line. If you want the three boxes to touch exactly, either:

- remove the whitespace between the tags in your HTML, or
- use Flexbox, which ignores whitespace between items.

If you want a deliberate gap between the boxes, add `margin` — but that is your design choice, not something you compute from the previous box's width.

**When *would* you calculate the previous box's width?**

You would typically do this when you are positioning an element manually, outside normal flow — for example, with `position: absolute`, where the browser does not lay the element out relative to its siblings. Fixed-width layouts, floats, and some responsive calculations can also require this. In that case, you would set `left` (or `margin-left`) to the previous box's total width so the two line up. In normal flow (block, inline, or inline-block), the browser handles the placement, and the calculation you need is simply "does the container have enough room for all the boxes?"

The core lesson is this: **under default `content-box` sizing, a box's total width is `content + padding + border`.** Forgetting padding and border is one of the most common reasons a layout overflows its container or wraps unexpectedly.

### 3.11 Summary: margin vs padding

| | Margin | Padding |
|--|--------|---------|
| Location | Outside the border | Inside the border |
| Purpose | Space *between* elements | Space between content and border |
| Affects background? | No (transparent) | Yes (background extends through padding) |
| Can be negative? | Yes (pulls elements closer) | No |
| Collapses vertically? | Yes | No |

A helpful mental model:

- **Padding** is like the cushioning inside a parcel: it keeps the contents away from the walls of the box.
- **Border** is the wall of the box.
- **Margin** is the space you leave between this parcel and other parcels on the shelf.

### 3.12 Quick reference: box model properties

| Property | Values | Notes |
|----------|--------|-------|
| `width` / `height` | `px`, `%`, `rem` | Content size by default |
| `padding` | 1–4 values, clockwise | Inside the border |
| `border` | `thickness style color` (order not enforced) | Grows outward under `content-box` |
| `border-width` | 1–4 values, clockwise | Override specific sides |
| `margin` | 1–4 values, clockwise | Outside the border; can be negative |
| `box-sizing` | `content-box` (default), `border-box` | `border-box` makes width include padding + border |

> **Key takeaway:** Every element is a box with four layers. Learn to calculate total width as `content + padding + border` (under default sizing), and remember that `margin` controls the space between boxes, not the box's own size.

## Putting It All Together

Here is a small example that uses everything covered in this guide:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>CSS Fundamentals Demo</title>

  <!-- Google Font -->
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  <link href="https://fonts.googleapis.com/css2?family=Caveat&amp;display=swap" rel="stylesheet">

  <style>
    /* Global reset for predictable sizing */
    * {
      box-sizing: border-box;
      margin: 0;
      padding: 0;
    }

    html {
      font-size: 100%; /* respect the user's browser default (usually 16px) */
    }

    body {
      background-color: #f4f4f4;  /* hex color */
      color: #333333;
      font-family: Arial, Helvetica, sans-serif;
      padding: 20px;
    }

    h1 {
      color: cornflowerblue;      /* named color */
      font-size: 2.5rem;          /* 2.5 × root size = 40px at 16px root */
      font-weight: 700;
      text-align: center;
      margin-bottom: 24px;
    }

    h2 {
      font-family: "Caveat", cursive;  /* custom web font */
      font-size: 2rem;                 /* 32px at 16px root */
      font-weight: 400;
      color: #5d3891;                  /* hex purple */
      text-align: center;
      margin-bottom: 16px;
    }

    .card {
      background-color: aliceblue;
      border: 2px solid #5d3891;
      border-radius: 6px;
      padding: 20px;
      margin: 0 auto 20px auto;   /* centered horizontally */
      max-width: 600px;
    }

    .card p {
      font-size: 1rem;            /* 16px at 16px root */
      line-height: 1.6;
      text-align: left;
    }
  </style>
</head>
<body>
  <h1>CSS Fundamentals</h1>
  <h2>A practical example</h2>

  <div class="card">
    <p>
      This card uses a <code>div</code> with padding, a border, and margin
      to create a contained, readable block of content. The heading above
      uses a named color, a custom Google Font, and a <code>rem</code>-based
      font size.
    </p>
  </div>
</body>
</html>
```

A few things to notice in this example:

- The `*` rule applies `box-sizing: border-box` to every element and removes default browser margins and padding. Browsers ship with their own default stylesheet (the **UA stylesheet**), which adds margins to headings, paragraphs, and other elements. These defaults vary slightly between browsers, so resetting them gives you a consistent baseline. With `border-box`, `max-width: 600px` on `.card` includes its padding and border.
- `html { font-size: 100%; }` keeps the root font size at the user's browser default (usually `16px`) rather than hard-coding it. Every `rem` value is based on this root size, so if a user has set a larger default font for accessibility, the whole page scales with it. If you wrote `font-size: 16px`, you would override that preference and make the page less accessible.
- `h1` uses a named color (`cornflowerblue`) and a `rem` font size; `h2` uses a hex color and a Google Font with a generic fallback.
- `.card` uses `margin: 0 auto 20px auto` to center itself horizontally while leaving 20px of space below it. `max-width: 600px` caps the card's width while allowing it to shrink on smaller screens.
- `line-height: 1.6` makes the paragraph text easier to read.

Try opening this in Chrome. Then:

1. Right-click the card and choose **Inspect**.
2. In the Styles pane, find the `.card` rule and toggle the `padding` off. Watch the layout change.
3. Scroll down to the box model diagram and edit the margin value live.
4. Switch to the **Computed** tab and find the final `font-family` of the paragraph.
5. Toggle the CSS off (if using a practice page with that control) and observe how the card looks with only browser defaults.

This workflow — write, inspect, adjust, copy back — is the daily rhythm of CSS development.
